## 宿題

- 取り組んだレベル：発展
- やったこと：
  - SWE-bench Verified を選んだ
    - データセット：https://huggingface.co/datasets/princeton-nlp/SWE-bench_Verified
    - 作成の説明：OpenAI「Introducing SWE-bench Verified」 https://openai.com/index/introducing-swe-bench-verified/
    - 元の SWE-bench の論文：https://arxiv.org/abs/2310.06770
  - Hugging Face で先頭の 3 件を読み、OpenAI のブログで作り方と検証の手順を調べた
- 結果：
  - 中身：12 の Python リポジトリで実際に解決された GitHub issue と、その PR から作った課題。エージェントには issue の本文とリポジトリだけを渡し、コードを直させる。採点は、PR に入っていたテストを実行して行う。FAIL_TO_PASS（直す前は落ち、直した後は通るテスト）と PASS_TO_PASS（前後とも通るべきテスト）の両方が通れば解決。LLM の採点は使わない
  - 読んだ問題（3 件とも astropy、難易度は「15 分〜1 時間」）：
    - astropy-12907：モデルを入れ子に組み合わせると、どの入力がどの出力に効くかを表す行列の計算を間違える。直すのは実質 1 行だが、行列の意味が分からないと場所を見つけられない
    - astropy-13033：時系列データで必須の列が足りないときのエラーメッセージが、「time」列だけを前提にしていて誤解を招く。テストはメッセージの文字列をそのまま比べるので、文言まで合わせる必要がある
    - astropy-13236：構造化配列を表に入れると、別の型に自動で変換される動作をやめる提案。7 行消すだけだが、この変換に頼っていたほかの処理への影響を考える必要がある
    - 自分なら、1 件目と 3 件目は issue だけでは直す場所が分からず、解けないと思った。LLM にとっても、テストを見せてもらえないまま、issue の文章だけで「どう直せば正解か」を当てる必要があるのが難しいと思う
  - 作成と検証：
    - Python の経験が豊富な開発者 93 人が、元のテストセットからランダムに選んだ 1,699 件に注釈を付けた
    - 観点は 4 つ。①issue の説明が十分に特定されているか ②テストが正しい解を落とさないか ③解くのにかかる時間 ④その他の問題
    - ①②は深刻度 0〜3 で付け、2 以上は捨てる
    - 先に社内で 50 件に確かなラベルを付けて、注釈者の選考テストに使った
    - 1 件を別々の 3 人が見て、いちばん厳しいラベルを採用した（1 人でも問題ありとしたら除外）
    - 結果、38.3% が「説明が足りない」、61.1% が「テストが正しい解を落とすおそれ」とされ、全体で 68.3% が除外された。残りから 500 件を選んだ（15 分未満が 196 件、1 時間超が 45 件）
    - 除外の例では、テストが PR の議論の中でしか決まっていない警告文との完全一致を求めていて、issue だけからはほぼ解けなかった
    - GPT-4o の解決率は、元の SWE-bench の 16% から、Verified では 33.2% になった。元のデータでは、解けない問題のせいで能力を低く見ていたことになる
  - 今日の評価セットとの違い：
    - 規模と作り手：今日は講師 1 人が作った 10 件。SWE-bench Verified は 93 人で 1,699 件を見て 500 件に絞り、1 件を 3 人で確認している
    - 採点：今日は人と LLM が T/F を付け、一致率で採点器を信じてよいかを見た。SWE-bench はテストの実行で機械的に決まり、採点者の主観は入らない。代わりに、「テストそのものが正しいか」を人が検証している
    - 割れたときの扱い：今日は人同士・人と LLM で割れたところを「まだ決めていないこと」として基準に書き足した。SWE-bench Verified は、3 人のうち 1 人でも問題ありとしたら捨てるという保守的な方法をとっていた
- 気づき・疑問：
  - 評価セットは、作るより「捨てるもの」を決める作業の方が重いと思った。7 割近くを捨てていて、捨てる前の数字で能力を測ると、モデルを過小評価してしまう
  - 今日の演習で「基準が決まっていないと LLM の判定が揺れる」のを見たが、SWE-bench でも「issue の説明が足りない」問題が 4 割近くあった。人が作った問題でも、決めていないことが混ざっている点は同じだと思った
