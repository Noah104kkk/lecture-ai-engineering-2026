## 宿題

- 取り組んだレベル：発展
- 変えた設定やデータ：
  - `make_sft_dataset.py` で用語集から116件を作り、5エポック学習（条件A）
  - Aに、別名の質問58件と、用語集にない語を断る例40件を足して214件で学習（条件B）
  - 用語集の検索も作って同じ問題を解かせた。質問の中に用語か別名があれば定義を返し、なければ「記載がありません」と返すだけのもの
  - 評価の質問は自分で26問用意した。同じ言い回し8問、言い換え10問、用語集にない語8問（断る例で使った語とは別の語）
  - ノートブック：`lectures/02/advanced_glossary.ipynb`、結果：`lectures/02/advanced_results.md`
- 結果（比較表や数字）：

| | 同じ言い回し | 言い換え | 用語集にない語 | 学習時間 |
|---|---|---|---|---|
| 学習前 | 0.125 | 0.2 | 0.0 | - |
| A 用語集のみ | 1.0 | 0.4 | 0.0 | 174秒 |
| B 断る例も追加 | 1.0 | 0.5 | 0.5 | 298秒 |
| 検索 | 1.0 | 0.5 | 1.0 | なし |

  - 採点はキーワードが入っているかどうかなので甘い。出力を読むと、言い換えで内容まで合っていたのはAで2問（LoRA、overfitting）、Bで3問（LoRA、429、overfitting）くらいだった
    - 例：A の fork の言い換えは「他人のコードを自分のアカウントに貼る作業」で、キーワードは入っているが中身が違う。B の Model Context Protocol は別の用語（Human-in-the-loop）の文と混ざっていた
    - 学習前の「fork」も、キーワードで正解になっているだけで「プログラミング言語の一種」という間違った答えだった
  - 同じ言い回しでも、Aは「コミットしない、メールに貼らない」のように定義の一部が変わることがあった。言い換えでは「APIキーはコメントに書く」という、用語集と逆の答えも出た
  - Bの断る例は、効いたのは「lec99-end タグ」「宿題の5レベル」「AIE2026の中間試験」「ベクトルデータベース」で、RAGなどは別の定義を混ぜて断定した。Aでは未知語でも全部それらしく答えた
  - 検索は言い換えのうち、用語が質問に入っていない5問を落とした。ただし落とすときは「記載がありません」と返すので、間違ったことは言わない
- ファインチューニングが向く場面・向かない場面についての考察：
  - 向く：出力の形式や答え方をそろえたいとき。演習のJSONは数分の学習でほぼ100%になった。今回も学習前の一般論や長い説明が、用語集の短い定義の形になった
  - 向かない：事実を正しく答えさせたいとき。覚えた文が混ざって、もっともらしい間違いになる。しかも見た目は用語集の文と同じ形なので、学習前より間違いに気づきにくいと思う
  - 検索と比べたメリット：検索の仕組みがいらず、モデルだけで動く。用語が質問に入っていなくても答えられることがある（今回は少なかった）
  - 検索と比べたデメリット：根拠を示せない、知らないと言えない（断る例を足しても半分）、用語集を直すたびに学習し直す（3〜5分）。検索なら用語集を直すだけで、答えは原文のまま
  - 今回の検索は単純な文字列の一致なので、言い換えに弱い。言い換えを拾うには検索側を改善するほうが筋がよさそう（第5回のRAG）
  - まとめると、中身は検索で渡して、形式はプロンプトやファインチューニングで整える、という分担がよいと思った
- 注意点：評価は26問だけで、学習も各1回。数字の差は小さいので、AとBの言い換えの差（0.4と0.5）は誤差かもしれない
